# UI-автотесты для zvet.ru

Python 3.11+, pytest, Playwright sync API, Faker и Allure. Сценарии рассчитаны на русскоязычный интерфейс магазина.

## Установка и запуск

Из каталога `project/` выполните следующие команды.

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python -m playwright install chromium
test -f .env || cp .env.example .env
```

Если в Linux отсутствуют системные библиотеки браузера, установите их командой `python -m playwright install --with-deps chromium`.

```sh
python -m pytest -q --collect-only           # собрать тесты без браузера
python -m pytest -s -v                     # весь набор, с шагами в консоли
python -m pytest -s -v -m negative         # негативные сценарии
python -m pytest -s -v -m smoke            # вход по почте
python -m pytest -s -v -m e2e              # оформление до отправки заказа
MANUAL_TESTS=1 HEADLESS=0 python -m pytest -s -v -m manual
```

## Демонстрация на практике

1. Запустите проверку формы входа в видимом Chromium. Сценарий использует синтетические данные, поэтому окно браузера можно показывать на экране. `BROWSER_SLOW_MO` замедляет действия браузера.

   ```sh
   HEADLESS=0 BROWSER_SLOW_MO=250 LOG_LEVEL=DEBUG python -m pytest -s -v -m negative -k missing-consent --alluredir=allure-results --clean-alluredir
   ```

2. Покажите строки ввода почты и пароля в консоли или в `logs/test.log`. Значения отображаются как `********`. Для показа вложений запустите контрольный тест отдельно. Он заполняет форму синтетическими данными и намеренно завершается с кодом 1. Форма входа остаётся открытой к моменту падения.

   ```sh
   HEADLESS=0 BROWSER_SLOW_MO=250 LOG_LEVEL=DEBUG python -m pytest -s -v demo/test_report_demo.py --alluredir=allure-results
   ```

3. Откройте Allure и выберите «Демонстрационное падение после заполнения формы входа». Покажите вложения «Скриншот при падении», «Текст ошибки» и «Журнал теста». В поле логина и пароля на скриншоте видны маски.

   ```sh
   allure serve allure-results
   ```

   Для просмотра отчёта прямо в браузере создайте один HTML-файл командой `allure generate allure-results --clean -o allure-report --single-file` и откройте `allure-report/index.html`. Allure CLI 2 устанавливается отдельно от Python-пакета и требует Java. При наличии Node.js можно вызвать CLI без глобальной установки командой `npm exec --yes --package=allure-commandline@2 -- allure serve allure-results`. [Установка Allure CLI](https://allurereport.org/docs/v2/install/).

4. Откройте [описание Page Objects](docs/locators.md). Для объяснения удобно начать с `LoginPage` и показать, как локатор ограничен активным окном и выбранной вкладкой.

## Публикация репозитория

Создайте пустой репозиторий в вашем Git-сервисе. Из корня проекта можно отправить коммит командой ниже, подставив адрес для Git из настроек репозитория.

```sh
git push <адрес-репозитория-для-Git> HEAD:main
```

Проверьте, что в опубликованном репозитории есть `.env.example`, а преподавателю выдан доступ. Отправьте ему ссылку на страницу репозитория. Локальные учётные данные, журналы и результаты прогонов исключены через `.gitignore`.

## Настройка .env

| Переменная | Когда нужна |
| --- | --- |
| `BASE_URL` | Адрес сайта. В шаблоне указан `https://zvet.ru`. |
| `TEST_EMAIL`, `TEST_PASSWORD` | Вход по почте и E2E. Укажите данные существующего тестового аккаунта. |
| `TEST_PHONE` | Вход по телефону. Укажите номер, уже привязанный к тестовому аккаунту. |
| `MANUAL_TESTS=1`, `HEADLESS=0` | Для входа по телефону. В открытом браузере решите капчу и нажмите «Войти», затем введите полученный SMS-код. Сайт отправляет код автоматически, а тест проверяет сеанс. `MANUAL_TIMEOUT` задаёт время ожидания каждого шага в секундах. |
| `SEARCH_QUERY` | Поисковый запрос с доступным для покупки товаром. |
| `CUSTOMER_PHONE`, `CUSTOMER_EMAIL` | Контакты заказа. По умолчанию используются `TEST_PHONE` и `TEST_EMAIL`. |
| `CUSTOMER_NAME`, `CUSTOMER_CITY`, `CUSTOMER_ADDRESS` | Тестовые данные для формы доставки. Укажите адрес, который принимает форма для выбранного города. |
| `LOG_LEVEL`, `LOG_FILE`, `REPORTS_DIR` | Уровень и направления диагностики. По умолчанию `INFO`, `logs/test.log` и `reports/`. |
| `BROWSER`, `HEADLESS`, `BROWSER_SLOW_MO`, `DEFAULT_TIMEOUT`, `NAVIGATION_TIMEOUT` | Движок браузера, видимость окна, замедление действий и таймауты. Временные параметры задаются в миллисекундах. |

При отсутствии учётных данных pytest пропускает сценарии, которым они нужны. Все негативные проверки используют синтетические данные. На сайте почтовый вход использует пароль, телефонный входит по SMS после капчи. Телефонный сценарий требует доступа к SMS привязанного номера.

## Сценарии

| Группа | Проверка | Ожидаемая реакция |
| --- | --- | --- |
| Позитивный | Почта и пароль, ТК-А02 | Ссылка на кабинет появляется и остаётся после перезагрузки. |
| Позитивный | Телефон, капча и SMS, ТК-А11 | После подтверждения кода появляется ссылка на кабинет. |
| Обязательное поле | Пустой пароль, ТК-А05 | Поле пароля выделено ошибкой, кнопка входа заблокирована. |
| Формат | Почта без точки в домене, ТК-А04 | Поле почты выделено ошибкой, кнопка входа заблокирована. |
| Формат | Телефон из 10 цифр | Поле телефона выделено ошибкой в телефонной форме. |
| Согласие | Корректные по формату данные без согласия, ТК-А09 | Поля проходят проверку, кнопка входа заблокирована. |
| Учётные данные | Синтетическая почта и неверный пароль, один набор ТК-А06 | Под обоими полями видно «Не верный логин или пароль». |
| E2E | Вход → поиск → карточка → корзина → форма заказа | Совпадают название, цена и артикул на соответствующих шагах. В корзине одна единица. Форма заполнена и показывает итог, кнопка «Оформить заказ» доступна. |

Идентификаторы ТК соответствуют таблице трассировки из учебного отчёта. E2E использует шаги ТК-А02, М10, М11, М18 и М19 в одном сценарии для вошедшего покупателя. Тест ожидает пустую корзину существующего тестового аккаунта. Для оформления используются сохранённые имя и телефон покупателя, если сайт уже подставил их в форму. В конце фикстуры удаляют добавленный артикул, завершают сеанс и закрывают контекст. Конечная точка сценария — заполненная форма перед нажатием «Оформить заказ».

## Локаторы

- `get_by_role` на вкладках, кнопке политики и кнопке заказа проверяет доступные имена интерфейса. Поле поиска в шапке определяется по `input[name="q"]`, поскольку текст подсказки меняется.
- `data-cy` идентифицирует поля и кнопку почтового входа. Область активного окна `._overlay.open` и выбранная панель отделяют форму от скрытого шаблона и телефонного входа.
- На карточке товара заголовок ищется по роли, текущая цена по классу `.detail-price__item.current`, артикул по подписи в списке характеристик. В корзине кнопка удаления ограничена строкой с нужным артикулом. Относительный XPath поднимается от поля входа к его обёртке для проверки ошибки.
- Форма входа обрабатывает события клавиатуры и потерю фокуса. Почта и пароль заполняются через `press_sequentially`. Телефон заполняется целиком, после чего тест сверяет цифры с номером из конфигурации.

## Диагностика и проверка запуска

Журнал поддерживает уровни DEBUG, INFO, WARNING и ERROR. При падении в `reports/<дата-запуска>/` сохраняются traceback и лог текущего теста. Когда страница уже открыта и доступна, хук сохраняет скриншот с масками на полях ввода, капче и обнаруженных контактных данных. С `--alluredir` эти же файлы прикрепляются к результату Allure. Для текстовой диагностики и статусов Allure применяется общая функция маскирования. В параметрах негативных тестов показываются только идентификаторы сценариев.

Для браузерного прогона Chromium должен запускаться в окружении с доступом к zvet.ru. Если окружение блокирует запуск браузера, pytest сохраняет traceback сбоя в `reports/`.
